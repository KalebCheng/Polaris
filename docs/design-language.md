# Polaris 控制台设计语言

> 面向控制台前端（`frontend/web`）的交互与视觉约定。新增 / 重构页面时以此为准；
> 令牌的唯一载体是 `src/styles/globals.css`，本文件只描述**怎么用**，不重复定义色值。
>
> **2026-10-15 UI 重构**：视觉基调从"靛蓝 + 描边面板"改为
> **画布 + 浮层面板 + 品牌主色 + 墨色选中胶囊**（对齐参考视觉）。
> 信息架构、路由与权限口径**未改动**——这一轮只换皮与重组页面骨架。
>
> **2026-10-22 材质与配色修订**：浮层面板从"纯白卡"升级为**半透明玻璃**（`.surface` / `.surface-strong`，
> 与顶栏、侧栏同一材质）；配色统一改为 **Radix Colors** 语义映射。
> 认证页不再使用"纯白 / 近黑"的独立配色，改为与控制台同一套画布与玻璃材质，仅额外保留品牌光晕与极淡网格。
>
> **2026-10-22 色相修订（当前）**：主色从"蓝 / 橙摇摆"收敛为**紫罗兰**——Radix **Violet** 承接 Logo 的紫色核心，
> Radix **Mauve** 提供带轻紫调的中性画布，琥珀只作品牌字标与警示点缀。这样既避免橙主色和警示色互相抢占语义，
> 也让品牌标识、主操作、选中态、图表首色落在同一色相家族里。主按钮与选中胶囊都走 Violet，
> 焦点环用 Violet 9，保证键盘导航可见。
>
## 0. 视觉基调（令牌层）

三层材质，缺一层画面就会"糊"：

| 层 | 令牌 | 浅色 | 暗色 | 用途 |
|---|---|---|---|---|
| 画布 | `--canvas` / `bg-background` | Radix Mauve 2 `#F9F8FA` | Radix Mauve 1 `#0F0E11` | 页面底色（`.app-canvas` 追加紫 / 青 / 琥珀三层极淡光晕） |
| 玻璃 | `--glass` / `.surface` | Mauve 1 的 78% 半透明叠层 | Mauve 2 的 82% 半透明叠层 | 卡片、表格容器、表单分区、侧边栏、顶栏 |
| 实底浮层 | `--card` / `.surface-strong` | Radix Mauve 1 `#FDFCFD` | Radix Mauve 2 / 3 `#161518` / `#232225` | 需要更强遮盖的弹窗、登录卡、下拉面板 |
| 选中 | `--ink` / `bg-ink` | Radix Violet 11 `#6550B9` | Radix Violet 9 `#6E56CF` | **"我在哪"**：顶栏选中胶囊、分段控件选中项、登录页主按钮 |

主色 `--primary`（Radix Violet 10 `#654DC4`）**只用于动作与链接**（主按钮、焦点环、可点文本）；
状态色 success / warning / info 一律"**淡底 + 同色字**"（`bg-*/10~14` + `text-*`），不用实心色块。

**圆角只有三档，禁止即兴取值**：

| 档位 | 值 | 用途 |
|---|---|---|
| `rounded-xl` | 18px | 控件（按钮 / 输入 / 下拉触发器）、内嵌小容器、KPI 卡片内的图标方块用 10px |
| `rounded-lg` | 12px | 卡片**内部**的代码块、行内小块 |
| `rounded-2xl` | 24px | 页面级面板 / 卡片 / 弹窗 |
| `rounded-full` | — | 胶囊：按钮、筛选器、徽章、状态药丸、导航项、分页 |

**投影只有三档**：`shadow-soft`（卡片、控件）、`shadow-lifted`（悬停抬起）、`shadow-pop`（浮层：下拉 / 弹窗 / 命令面板）。
玻璃材质自带一道 `inset 0 1px 0 var(--glass-highlight)` 内高光；暗色下投影几乎不可见，
**分层靠描边与内高光**，不要靠加黑阴影。

写页面的默认组合是：

```
surface rounded-2xl
```

需要更强遮盖、不希望画布透上来的浮层（弹窗、登录卡）用 `surface-strong`。
`.surface` 是组件层类，仍可用 utility 覆盖背景 / 描边（如交互卡片的 hover 描边）。
`outline` 按钮同为玻璃材质（`bg-card/70 + backdrop-blur`），落在玻璃卡里不会变成一块"白药丸"。

## 1. 总原则

- **安静克制的工作台**：一屏里"我在哪 / 这是什么页面 / 关键数字是多少"三层必须先被读到，其余退到次级灰。
- **画布不留裸内容**：长表格、表单、统计必须落在卡片上；画布只承载留白与光晕。
- **认证页（登录 / OAuth 回调）是唯一品牌场域，但同样克制**——与控制台同一套雾紫画布与玻璃材质，
  额外叠一层品牌光晕与极淡网格；单列居中、**品牌深紫主按钮**（`.auth-scope` 把 `--primary` 重映射为 `--ink`，
  与登录方式标签选中态、控制台导航选中胶囊同一语义；其主按钮与胶囊仍是同一套 `@/shared/ui` 组件），
  品牌色只留在标识与焦点环上。
- **认证页提交按钮是有形态变化的**：提交后从整宽缓动收成一个圆形、文字淡出、圆内转圈，直到结果返回
  （`features/auth/components/submit-button.tsx`，宽度与缓动走 `--motion-pill-size` / `--motion-spring`）。
- **贴边铺满，不居中限宽**：控制台内容区随视口伸展，只保留 `px-4 sm:px-6 lg:px-8` 呼吸间距。
  表单在超宽屏上会显得拉长时，可**局部**限宽（左对齐，不用 `mx-auto` 居中）。
- **一屏一件事**：字段多不等于一屏铺满——按语义分组、按重要性分层，常见项在前、高级项收起。
- **改哪看哪**：有即时反馈的配置（品牌、主题）配实时预览，而不是"保存后再回来看"。
- **不编数据**：没有后端来源的趋势 / 同比 / 排行一律不做（参考视觉里的 `+20% 同比上月` 需要历史快照，
  当前后端没有——宁缺勿造）。

## 2. 页面骨架

- `PageShell`（`widgets/layout/page-shell.tsx`）：标题（`text-[26px]`、负字距）+ 描述（`text-[13px]` 次级灰）
  + 操作区 + 可选二级标签（`subnav`）。内容区 `mt-6` 起，板块间距 `gap-5`。
- **页头首屏可以有个性**：平台总览用"问候语 + 日期"作为标题（`dashboard.greeting` / `formatLongDate`），
  其余页面用资源名 + 一句话口径。
- 顶部导航（`TopBar`）+ 工作区侧边栏（`AppSidebar`）共同构成外壳；两者都是玻璃浮层，
  同属"画布上的面板"，不是贴边的另一条色带。
- **二级页的页头归组级布局**（`SubnavPageLayout`）：页头（标题 / 描述 / 操作）与二级导航由布局渲染，
  页面只提供内容 —— 这样导航在路由切换中不卸载，才能像顶栏那样滑动（见 §5.0）。
  页面的操作按钮用 `usePageHeaderActions` portal 进布局页头，仍留在页面作用域里。
- **二级导航选形态**（`variant`）：二级之间是"同一页的不同切片"、且数量少 → 横向胶囊（`tabs`，安全管理）；
  二级之间彼此独立、像一组页面 → **左侧纵向菜单**（`menu`，系统设置走 `PageShell` 的 `sidebar` 槽位：
  布局切成"左栏 + 右内容"，页头留在右栏内，与组织管理的资源侧栏同级；`md` 以上才是两栏，窄屏折到内容上方）。

## 3. 列表页模式

标准四件套，缺一不可：

| 组成 | 组件 | 说明 |
|---|---|---|
| KPI 行 | `SummaryStrip`（默认 `cards`） | 顶部对齐口径：白卡 + 图标方块 + 大数字 + 可选口径说明；`to` 给出时整卡可点 |
| 工具栏 | `ListToolbar` | 胶囊搜索框 + 胶囊筛选下拉 + 右侧计数 |
| 内容区 | `ResourceTable` / `ResourceCards` | 两种形态二选一（见下），加载骨架 / 空状态 / 分页口径一致 |
| 分页 | `ListPagination` | 由内容区组件内置（当前页＝品牌深紫胶囊） |

**表格还是卡片：按"要比对还是要识别"选**

| 形态 | 组件 | 适用 | 现状 |
|---|---|---|---|
| 表格 | `ResourceTable` | 列多、需要逐列比对或扫读数值 | 用户、用户组、角色、权限、证书、令牌、会话、审计、应用账号 |
| 卡片网格 | `ResourceCards` | 资源有图标 / 名称 / 标识 / 状态徽标，"一眼认出这是个什么"比逐列比对更重要 | **组织**、**应用** |

- 卡片是网格子项，统一 `RESOURCE_CARD_CLASS`（`surface rounded-2xl` +
  悬停抬起），并固定 `flex h-full flex-col`：同一行等高，页脚靠 `mt-auto` 贴底对齐；
  栅格 `sm:grid-cols-2 xl:grid-cols-3 2xl:grid-cols-4`，加载态用同尺寸卡片骨架。
- 卡片信息自上而下＝**标识（图标 + 名称 + 业务标识徽标）→ 状态 → 描述 → 关键字段 → 页脚操作**。
  一张卡只常驻**一个**主操作（组织＝进入工作区、应用＝编辑），其余（编辑 / 端点 / 重置密钥 / 删除）
  收进 `RowActionsMenu`；内置（不可删）资源**不给删除入口**，而不是点完再报错。
- 弹窗 / 卡片内部的次级统计用 `SummaryStrip variant="inline"`（紧凑一行），**别在弹窗里铺四张 KPI 大卡**。
- 状态一律用 `StatusPill`（柔和底色 + 前置圆点），行操作用 `RowActionsMenu`（主操作常驻 + 其余收进下拉）。
- 表头 `11px` 次级灰、行高 `h-14`、分隔线 `border-border/60`；数值列加 `tabular-nums`。

## 4. 表单与向导模式

### 4.1 何时用向导

- **字段彼此无依赖** → **单页分区表单**：`PageShell` + 若干 `FormSection`，每个分区内部多列并排
  （`grid gap-x-6 gap-y-5 sm:grid-cols-2 xl:grid-cols-4`），**一行铺满内容区**。
  典型：用户新建/编辑（20 个字段彼此无关，一屏看完，改一个字段不必先点三次「下一步」）。
- **阶段之间确有依赖**（后一步的选项取决于前一步）→ 才用**分步向导** `FormWizard`。
  典型：应用创建（登录方式决定后续要配什么），提供商（类型决定字段 schema）。
- 判断口径：把字段切成步骤只因为"一屏放不下"→ 先想想能不能分区多列；**能一屏放完就不要切步骤**。
- **单例配置**（"只有一份"的设置，如系统设置 › 存储设置）→ **实例卡片 + 页内分区编辑**：
  卡片先讲清"当前是哪一个 / 谁在用它 / 能做什么"（状态药丸 + 元信息 + 行内动作：测试连通性 / 修改配置 / 清除配置），
  点「修改配置」在**页内**展开字段，保存后卡片立即回到新状态；不切步骤、不开弹窗（字段彼此无依赖）。
- 向导**不做强制线性**：步骤条可点击回跳；只对"下一步"做必要门禁（如名称必填）。
- 向导的**步骤条与操作按钮同处吸顶头部**：滚动到表单深处时「上一步 / 下一步 / 提交」也始终在手边，
  不必滚到底才能提交（已不再使用吸底操作栏）。

> 约定：应用的「新建 / 编辑」采用**五步向导**（基本信息 → 登录方式 → 注册与自助服务 → 客户端与端点 → 安全与令牌），
> 创建与编辑复用同一组件；见 `features/iam/components/application-wizard.tsx`。
>
> 应用标识是**标识（`code`）**（进 URL、创建后不可改）、人类可读名是**名称（`name`）**；
> 客户端 ID / 密钥由服务端生成，**不出现在表单里**，仅在创建完成页（与重置密钥后）一次性展示。

### 4.2 组件

| 组件 | 位置 | 用途 |
|---|---|---|
| `FormWizard` | `shared/components/form-wizard.tsx` | 顶部步骤条 + 单步内容 + 吸顶操作栏 |
| `FormSection` | `shared/components/form-section.tsx` | 一个语义分区；`collapsible` 收高级项 |
| `SwitchField` | `shared/components/switch-field.tsx` | 开关行（名称 + 后果说明 + 整行可点） |
| `TagInput` | `shared/components/tag-input.tsx` | 标签集合（chips 输入：回车/逗号添加、可粘贴多个） |
| `RepeatableList` | `shared/components/repeatable-list.tsx` | 多值行式编辑器（回调地址等，一行一条可增删） |

搭配规则：

- **`FormSection` 不自带栅格**：字段必须由页面自己套一层
  `<div className="grid gap-4 sm:grid-cols-2">`（需要整行时给字段加 `sm:col-span-2`）。
  直接把 `Field` 串在分区里 = 一列铺到底（真实事故：新建用户表单在 2560px 宽屏上被拉成一堵墙）。
- **单页分区表单：分区卡片全宽、内部多列**，一行铺满内容区。字段宽度靠**列数**控制
  （4 列时每列约 400–450px 最舒服），不要给整页套一个窄的 `max-w-*` 然后让右边空着。
- **向导页（`FormWizard`）的宽度由页面自己管**，单列 `max-w-2xl`、两列 `max-w-3xl`。
  **别改共享 `FormWizard` 的布局**：它被应用 / 提供商 / 身份连接 / 机构 / 用户五处复用。
- **同一个标题只出现一次**：`FormWizard` 的步骤头部已经渲染了本步标题与说明，
  步骤内容里的 `FormSection` 就**不要再写一遍同样的 `titleKey`**（省略 `titleKey` 即"无标题卡片"）。
- **每个分区只挂在它所属的步骤里**：`FormWizard` 的 `children` 必须写在步骤条件内。
- 布尔策略用 `SwitchField` 并尽量给 `descriptionKey`（讲清**开启后的后果**）。
- 少量互斥选项用**分段控件**（`Tabs`，选中项＝品牌深紫胶囊），不要下拉。
- **资源引用一律下拉**：多选 `MultiSelect`、可搜索单选 `Combobox`；禁止把资源列表平铺成勾选框。

### 4.3 创建 vs 编辑

- **创建**：末步提交后停留在**完成页**，一次性展示 `client_id` / `client_secret` 与各端点（可复制）。
  **密钥仅此一次完整展示**。
- **编辑**：末步提交即保存并返回列表。
- 任一模式：有未保存修改时，离开要拦截（页内 `ConfirmDialog` + `beforeunload`）。

### 4.4 品牌来源

- **管理端控制台一律使用平台品牌**（`BrandMark` / `BrandLockup` 的内置矢量）：包括平台层页面**与**组织工作区。
- **只有面向终端用户的入口**才用租户品牌：用户门户 `/portal/**` 用所属组织 Logo/Favicon；
  登录 / 注册 / 魔法链接页由 `/auth/app-info` 按应用与组织渲染。
- 判定唯一入口：`features/iam/lib/brand-scope.ts`（禁止用 localStorage 的"上次访问组织"驱动控制台品牌）。

## 5. 框架：顶栏 / 侧边栏 / 快速跳转

- **顶栏＝悬浮玻璃岛**（`widgets/layout/top-bar.tsx`，高 `h-16`）：**不贴边**，
  左右留白与内容区**同一套刻度**（`px-4 sm:px-6 lg:px-8`）+ `pt-3` 露出画布；
  面板为 `.surface`（半透明玻璃 + 背景模糊 + 内高光 + `rounded-2xl`），
  画布底色从背后透上来。内容顺序：品牌标识 → 平台级导航（胶囊，选中项 `bg-ink text-ink-foreground`）
  → 全局快速跳转 → 账号菜单；窄屏平台导航折叠为**同一个玻璃岛内的第二行**（可横向滚动），
  因此外壳始终"一块玻璃"，而不是"贴边色带 + 一条分隔线"。
  用户门户（`PortalLayout`）用同一套玻璃岛。

### 5.0 弹性滑块（导航 + 分段控件共用）与动效

"选中态＝一块滑过去的深紫胶囊"这套表现由 `shared/ui` 的 **`useSlidingPill`（量测）+ `SlidingPill`（渲染）**
提供，两处容器共用同一份实现与同一套令牌（`.sliding-pill-indicator`）：

| 容器 | 选中项选择器 | 现状 |
|---|---|---|
| `NavPills`（顶栏 / 门户导航，`widgets/layout/nav-pills.tsx`） | `[data-active="true"]` | 路由导航，`<a>` |
| 二级导航（`SubnavPills` 横向胶囊 / `NavMenu` 纵向菜单 ← `subnav-page-layout.tsx` 的 `variant`） | `[data-active="true"]` | 换页导航（**不是** tab），由**组级布局**常驻渲染 → 与顶栏同样能滑 |
| 纵向菜单（`NavMenu` ← `widgets/layout/nav-menu.tsx`：工作区资源侧栏 `WorkspaceNav` 与平台二级菜单共用） | `[data-active="true"]` | 换页导航；`orientation="vertical"` 只是把位移轴换成 Y 轴（行满宽、行首图标、圆角收成与行一致）。**整块菜单只有一个容器**，分组抬头作为"不可选中的条目"一起进列表——跨分组切换才是同一块滑块的位移（每个分组各渲染一份列表＝没有过渡，`nav-menu.test.tsx` 锁定"同一个 DOM 节点 + 位移真的变了"）。**条目不许自带底色**（`bg-primary/10` / `bg-ink` 都会与滑块重影） |
| `Tabs` 默认形态（分段控件：提供商类别 / 身份连接方向 / 任务状态 / 用户详情分区） | `[data-state="active"]` | Radix Tabs，`<button>` |
| `TabsList variant="plain"` | —（不量测） | 下划线标签（登录页的登录方式切换），样式全交调用方 |

- **量测必须由容器组件自己调用**：React 的 layout 阶段先递归子树、再给 host 节点挂 ref，
  子组件的 `useLayoutEffect` 里读容器 ref 恒为 `null`（真实踩过：滑块一直不出现）。
- **量测时机不能只靠 React 重渲染**：容器**未必**会重渲染——Radix 分段控件是非受控的
  （`TabsList` 不消费选中值，点击后只有触发器 `data-state` 变了），菜单折叠、增删条目同理。
  因此 hook 每次提交都量一次（值相同不 setState）＋订阅容器的尺寸变化与
  `data-active` / `data-state` / 子树变化；调用方不再需要传"量测签名"
  （早先靠它驱动，漏传一次滑块就不动）。
- **换页导航要能滑，标签必须常驻**：滑块靠 CSS transition，而 transition 只能过渡**同一个元素**的属性变化。
  顶栏导航不卸载所以能滑；`/security/*`、`/settings/*` 的二级标签是"点一下换路由"的换页导航，
  若由各页自己渲染（`PageShell` 的 `subnav`）就会整块重挂载 → 滑块每次都是新元素、只能瞬时落位
  （首帧 `data-ready="false"` 本就是为"不要从最左飞过来"设的）。
  因此这两组二级页统一用**组级布局**（`features/iam/pages/{security,settings}-layout.tsx`）：
  页头（标题 / 描述 / 操作）与标签都归布局，页面只提供内容，标签在路由切换中不卸载。
  回归口径：`subnav-page-layout.test.tsx` 锁定"切换后滑块是**同一个 DOM 节点**"——
  只断言"存在滑块"会漏掉这类"看着同形、其实每次都重建"的失败。
- 缓动与时长是令牌（`globals.css` 的 `--motion-spring` / `--motion-pill-move` / `--motion-pill-size`），
  组件里不写死数值：位移 420ms、宽高 340ms，都是 `cubic-bezier(0.34, 1.56, 0.64, 1)`（终点带回弹）。
- **位移与尺寸用不同时长是刻意的**：滑块在换项时会被"拉长再收回"，弹性手感来自这里。
- 回归口径：选中项只改文字色（`text-ink-foreground`），**不得再自己加 `bg-ink`**——
  否则会出现"一块动的 + 一块不动的"重影（`nav-pills.test.tsx` / `tabs.test.tsx` 双双锁定）。
- 首帧关闭过渡（避免加载时滑块从最左飞过来）；`prefers-reduced-motion` 下 transition 直接置空；
  找不到选中项时不渲染滑块。
- 量测用"两者 rect 之差 + 滚动偏移"：保留亚像素精度，窄屏横向滚动的导航里也算得对。

> **对齐是硬约束**：玻璃岛的边、内容卡片的边、侧边栏浮层的边必须在同一条竖直线上（左右与上下同刻度）。
> 实测口径：`top-bar.tsx` 的 `px-4 sm:px-6 lg:px-8` + `pt-3` ↔ `platform/workspace-layout` 的
> `px-4 py-5 sm:px-6 sm:py-6 lg:px-8` ↔ `app-sidebar.tsx` 的 `py-5 pl-4 sm:py-6 sm:pl-6 lg:pl-8`。
> 只改其中一处就会出现"内容比菜单栏缩进一截"的错位（真实反馈）。
- **工作区侧边栏**（`widgets/layout/app-sidebar.tsx`）：画布上的玻璃圆角浮层（`surface` / `rounded-2xl`），
  组织切换器在最上；组织内资源项选中态为 `bg-primary/10 text-primary`（这里是"组织内定位"，
  与顶栏"平台级定位"用两种颜色区分层级）。
- **全局快速跳转**（`widgets/layout/nav-search.tsx`）：把两级导航拍平成可搜索面板（`Ctrl/⌘` 心智：
  输入 → 上下键 → 回车跳转）。它**复用 `nav-config` 的导航结构与 `can()` 门禁**——
  菜单里因权限隐藏的，这里也搜不到；不新增第二份菜单清单。
- **禁止加"假控件"**：参考视觉里有全局搜索框、通知铃铛、导出按钮，但没有对应能力的一律不做
  （红线：不留未接线的死代码）。要做就先接后端能力。

## 6. 文案与国际化

- 禁止硬编码文案，统一走 i18n；新增字段用**独立 key**（不要复用页面标题 key）。
- 中英 key 集合必须**完全一致**、无空文案——由 `shared/i18n/i18n.test.ts` 锁定；
  代码中静态引用的 key 必须存在——由 `shared/i18n/usage.test.ts` 锁定。
- 日期 / 时段这类**语序随语言变化**的文案走 `Intl`（`shared/lib/long-date.ts`），不要手写拼接模板。

## 7. 红线（摘自 AGENTS.md §7.3，前端）

1. 页面 / feature 只允许从 `@/shared/ui` 导入 UI 组件，禁止裸 HTML 控件组合。
2. feature 之间不互相引用，经 `shared/` 通信。
3. 禁止裸色值与任意字号 / 间距，用 Tailwind utility 或语义化 CSS 变量（含本文件第 0 节的圆角 / 投影档位）。
4. 文案走 i18n；页面懒加载；不留未接线的死代码。
